    03 — How I write tests

    Tests are code. I write them like it.

    • /01

      Readable over clever

      Tests read like specs, so a failing test explains what broke without anyone digging through the code.

    • /02

      Deterministic by design

      Isolated data, web-first assertions and no hard sleeps. A flaky test gets fixed, not retried forever.

    • /03

      The right layer for each check

      Push checks down the pyramid: test logic through the API and keep the slow end-to-end runs for real user journeys.
